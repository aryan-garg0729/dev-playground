# Forks and Pull Requests

On GitHub, teams don't usually push straight to `main`. They use **pull requests** (PRs):

1. Push your work to a branch.
2. Open a pull request on GitHub: "please merge my branch into `main`".
3. Teammates review the changes, comment, and ask for fixes.
4. When everyone's happy, someone clicks **Merge**.

For projects you **don't** have permission to push to (most open-source projects), there's one extra step: a **fork**. A fork is your own copy of someone else's repository, on your GitHub account. You push to your fork, then open a pull request from your fork to the original project.

You want to fix a typo in a popular open-source project. You don't have permission to push to it.
